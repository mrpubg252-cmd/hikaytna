# نظام سحب ومولد الـ API للمسلسلات والسيرفرات بمانع إعلانات (Admin Scraper & API Engine)

أداة متكاملة وذكية في لوحة تحكم الأدمن لإنشاء وإدارة API سحب المسلسلات والصور وتفاصيل الحلقات وسيرفرات البث النظيفة الخالية من الإعلانات المنبثقة، مع إمكانية نشرها مباشرة في تطبيق "حكايتنا" أو تصديرها عبر REST API نظيف.

---

## مراجعة المستخدم والقرارات المعمارية الرئيسية

> [!IMPORTANT]
> تم تصميم النظام ليعمل بطريقتين مرنتين معاً تلبي جميع احتياجات الإدارة:
> 1. **السحب والاستيراد المباشر إلى قاعدة بيانات التطبيق (Firestore)**: بنقرة زر واحدة بعد المعاينة لإتاحة المسلسل وحلقاته فوراً لمستخدمي "حكايتنا".
> 2. **مولد الـ API (RESTful Endpoints + API Keys)**: توفير روابط JSON نقية ومحمية بمفتاح API لجلب المسلسلات والحلقات وسيرفرات البث النظيفة برمجياً.

- **مانع الإعلانات المدمج في السيرفرات**: يتم تمرير روابط مشغلات الفيديو عبر طبقة بروكسي ذكية في السيرفر تقوم بتجريد النوافذ المنبثقة (Popups/Redirects) وسكريبتات التعقب الإعلاني، وإرجاع مشغل نظيف جاهز للعرض.
- **مصادر السحب المدعومة**: دعم إدخال روابط مباشرة لأي مسلسل (قصة عشق، أكوام، لودي نت، الوي تي في) مع استخراج تلقائي للعنوان، البوستر، الحلقات، وقائمة السيرفرات.

---

## 1. نظرة عامة ومفهوم الأداة

- **ما تقدمه الأداة**: قسم جديد متطور داخل لوحة تحكم الأدمن (`AdminScreen.tsx`) بعنوان **"مولد وسحب الـ API"** يتيح للإدارة إدخال رابط مسلسل أو موقع، ليقوم النظام آلياً بتحليل الصفحة، سحب صور البوستر، أسماء وأرقام الحلقات، وسيرفرات المشاهدة مع تطبيق مانع الإعلانات وتوليد روابط تشغيل مؤمنة.
- **الجمهور المستهدف**: إدارة تطبيق "حكايتنا" لتغذية محتوى المسلسلات وسيرفراتها بسرعة فائقة ودون الحاجة لإدخال الحلقات وسيرفراتها يدوياً.
- **القيمة الأساسية**: توفير ساعات طويلة من العمل اليدوي، والحصول على مسلسلات بحلقاتها الكاملة وسيرفرات بث نقية بدون إعلانات مزعجة للمستخدمين.

---

## 2. تجربة المستخدم والتصميم البصري

### تدفق تجربة الأدمن (User Flows):
1. **فتح تبويب "مولد وسحب الـ API" في لوحة التحكم**:
   - واجهة عصرية منسجمة تماماً مع طابع لوحة الإدارة الداكن (`#0A0A0C` مع لمسات أحمر كرزي `#DC2626` وحدود دقيقة `border-white/10`).
2. **سحب محتوى مسلسل جديد**:
   - حقل إدخال ذكي لرابط المسلسل (أو اسم المسلسل للبحث السريع).
   - زر تفاعلي **"بدء الاستخراج الذكي ⚡"** مع شريط تقدم وحالة مباشرة أثناء معالجة الحلقات والسيرفرات.
3. **معاينة النتائج قبل الحفظ**:
   - بطاقة تفاعلية تعرض البوستر، العنوان، التصنيف، وعدد الحلقات المستخرجة.
   - قائمة الحلقات مع سيرفرات البث الخاصة بكل حلقة وإمكانية معاينة المشغل النقي مع مانع الإعلانات مباشرة للتأكد من عمله.
4. **النشر أو التصدير**:
   - زر **"نشر مباشرة إلى تطبيق حكايتنا 🎬"**: لحفظ المسلسل وجميع حلقاته في قاعدة البيانات فوراً.
   - قسم **"مولد الـ API الخارجي 🔑"**: يولد رابط API خارجي (مثال: `/api/v1/scraper/series`) مع مفتاح سري للتصدير والمزامنة كـ JSON.

---

## 3. القرارات المعمارية والتقنية

- **القرار الأول: معالجة السيرفرات ومانع الإعلانات في الباك إند (`server.ts`)**:
  - *النهج*: إنشاء مسارات جديدة مخصصة:
    - `POST /api/v1/scraper/extract-series`: لاستخراج كافة بيانات المسلسل، الحلقات، والسيرفرات.
    - `GET /api/v1/scraper/clean-stream`: لتوليد كود المشغل النظيف المجرد من الإعلانات المنبثقة وسكريبتات التوجيه.
    - `GET /api/v1/scraper/api-key`: لإدارة وتوليد مفاتيح الوصول للـ API.
  - *السبب*: تجاوز قيود الـ CORS، وحماية مصادر البث، ومنع الإعلانات على مستوى السيرفر قبل وصول الكود للمتصفح.

- **القرار الثاني: الحفظ الهجين (Firebase + On-Demand API)**:
  - *النهج*: إمكانية حفظ المسلسلات المستخرجة في مجموعة Firestore كمسلسلات رسمية تظهر فوراً في الواجهة الرئيسية، أو استدعاؤها عبر الـ API حسب الطلب.
  - *السبب*: مرونة قصوى تضمن استقرار السيرفر وسرعة التصفح داخل التطبيق.

## خطوات التنفيذ القادمة بعد الاعتماد:
1. بناء محرك السحب وتجريد الإعلانات في `server.ts` لدعم استخراج المسلسل، الحلقات، والسيرفرات النقية.
2. إضافة تبويب "مولد وسحب الـ API" في `src/screens/AdminScreen.tsx` مع المعاينة التفاعلية وأداة إدارة الـ API.
3. اختبار وفحص السحب والتشغيل النقي والتأكد التام من خلو التطبيق من أي أخطاء تجميعية عبر `compile_applet`.
